# SIMO Player — Real SUMO Playback Implementation Plan

## Context

The reference page (`../web/index.html`) demonstrates a record → pack → playback pipeline:
1. **Record** (`sim/video_capture.py`): `sumo` runs offline with `--fcd-output --summary-output --seed 42 --step-length 1 --time-to-teleport 300 --max-depart-delay 1800`
2. **Pack** (`sim/video_pack.py`): Produces `run.bin` in `BLGR` binary format — per-frame vehicle records (9 bytes: id, x dm, y dm, angle/2, speed×8, type) + 5×u16 stats per frame
3. **Playback** (inline script from `sim/sim_player.py`): Lazy fetch, DataView parse, RAF loop with 1 Hz interpolation and wrap-safe angle lerp, canvas rendering with signal dots, speed-colored vehicles, HUD counters

**Current simo-player already has the playback half:** `TrafficSimEngine` decodes the identical format from base64, interpolates identically, `makeSimOverlay` renders lanes/signal dots/speed-colored rotated rects, `SimPanel` has the 5 HUD counters + controls.

**Gap:** Only `CATALOG[0]` (Balagere) gets the real stream — `isRealSim()` hardcodes it; user submissions use `_synthVehicles()` fake traffic. No path exists for a submitted bundle to become a recorded run.

---

## Phase 1 — Contributor Packer (`tools/pack_run.py`)

New Python tool in `simo-player/tools/`:

```bash
pack_run.py --net n.xml --rou r.xml [--cfg c.xml] --scenario today,proposed... -o out.simo.json
```

**Steps:**
1. **Shared geometry extraction** — move `geom()` (lanes/arms/phases/stops/links from `.net.xml`) from `sim/build_player.py` into a shared module imported by both the case-study build and this packer.
2. **SUMO discovery** — reuse the chain from `convertScript`: `$SUMO_HOME` → `/Library/Frameworks/EclipseSUMO.framework/...` → `PATH`.
3. **Run SUMO** — exact flags from `video_capture.py:34-38`.
4. **Pack** — generalize `video_pack.py`'s BLGR logic from hardcoded 2 scenarios / 900 frames → N scenarios / arbitrary frames.
5. **Emit `.simo.json`** — shape consumed directly by `TrafficSimEngine._scenMeta`:
   ```json
   {
     "nFrames": 900,
     "bounds": [x0, y0, x1, y1],
     "scenarios": {
       "today": {"frames": "<b64>", "stats": "<b64>"},
       "proposed": {"frames": "<b64>", "stats": "<b64>"}
     },
     "geometry": {"lanes": [...], "arms": {...}, "phases": [...], "stops": {...}, "links": {...}}
   }
   ```

## Phase 2 — Per-Entry Streams in Player

**Data model:** `catalog[i].scenarios[key].frames` (base64) alongside existing `stats`. The engine decode path already supports this.

**Code changes:**
- `app.js:839-853` — delete `isRealSim()` and the `BALAGERE_STREAM` special-case in `engineFor` / `scenarioGeoOf`; engine falls through to `meta.frames`.
- **Lazy loading with `file://` constraint** — `fetch()` fails on `file://` (the web player itself errors). Streams live in `streams/<id>.js` loaded via dynamic `<script>` injection with a JSONP-style callback, keeping `data.js` small.

## Phase 3 — Submit Flow Integration

- `classifyUploadFile` gains `.simo.json` acceptance.
- Wizard parses the pack onto the draft; `approveDraft` carries scenarios-with-frames into the catalog.
- Raw net/rou/cfg uploads remain as synthetic preview (labeled), with the packer offered for download.
